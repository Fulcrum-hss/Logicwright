# CM_Cylinder Implementation

This document defines the first executable Logicwright generation path: `CM_Cylinder`.

## 1. Principle

`CM_Cylinder` is a Logicwright standard library block. It is not generated differently for every project.

Logicwright generates project-specific artifacts around the standard block:

- interface DB entries
- FB call source
- I/O tag table export
- HMI faceplate binding table
- alarm binding table
- audit manifest

This keeps the cylinder logic governed, versioned, reviewable, and reusable.

## 2. Standard Library Source

Standard PLC sources are stored in:

```text
libraries/tia/logicwright-standard/v0.1.0/plc/CM_Cylinder/
  CM_Cylinder_Types.scl
  CM_Cylinder.scl
```

Import order:

1. `CM_Cylinder_Types.scl`
2. `CM_Cylinder.scl`
3. generated project sources

## 3. Input Files

The generator reads:

- `templates/input-package/04-io-list.csv`
- `templates/input-package/05-module-cylinders.csv`
- `templates/input-package/08-alarms.csv`
- `templates/input-package/09-hmi-requirements.csv`

Only cylinder rows with `template_id=CM_Cylinder_V0_1` are generated by this path.

## 4. Generate Artifacts

Run:

```powershell
dotnet run --project generators\Logicwright.CylinderGenerator\Logicwright.CylinderGenerator.csproj -- --input templates\input-package --output artifacts\generated\cm-cylinder
```

Generated files:

```text
artifacts/generated/cm-cylinder/
  plc/sources/dbCylinderInterfaces.scl
  plc/sources/FC_CallCylinders.scl
  plc/tags/IoTags.generated.csv
  hmi/CylinderFaceplateBindings.generated.csv
  alarms/CylinderAlarmBindings.generated.csv
  audit/manifest.json
```

## 5. TIA Integration Plan

For the current implementation stage, generated files are reviewable artifacts.

The next TIA Connector steps are:

1. Import `CM_Cylinder_Types.scl`.
2. Import `CM_Cylinder.scl`.
3. Import `dbCylinderInterfaces.scl`.
4. Import `FC_CallCylinders.scl`.
5. Import or create PLC tag tables from `IoTags.generated.csv`.
6. Compile the PLC software.
7. Read compile diagnostics.

HMI faceplate binding and alarm binding are exported as CSV contracts first. The following implementation stage will use them to create or update WinCC Unified HMI tags, faceplate instances, text lists, alarms, and archives.

## 6. Safety Boundary

`CM_Cylinder` does not generate safety logic and does not bypass safety circuits.

Safety-related signals may be displayed or used as read-only permissive inputs only when the project owner explicitly defines the interface. Safety program generation remains a manual engineering responsibility.
